# repo tamagotchi: ясный журнал проекта

## цель

сделать из текущего статического приложения цельный мини‑проект: человеку сразу понятно, что он загружает, что увидит, откуда берутся сигналы и что можно сделать с результатом. сохранить механику анализа, питомца, share‑снимка и экспорта; привести все пользовательские тексты, README и визуальный слой к голосу тимофея: коротко, спокойно, с начала предложения со строчной буквы, если это не имя или техническое обозначение.

## что сохраняем

- анализ публичной ссылки github, zip и папки целиком в браузере;
- детерминированные пять характеристик и объяснение сигналов;
- локальную обработку файлов, ограничители zip и защиту от вставки html;
- svg‑питомца, восстановление результата по hash, экспорт svg/png;
- простую публикацию через github pages без серверной части.

## что меняем

1. **тексты интерфейса.** первый экран отвечает на три вопроса: что это, что нужно дать приложению и что произойдёт после загрузки. кнопки называют фактическое действие. ошибки объясняют причину и следующий шаг. подписи к метрикам показывают, что это сигналы структуры, а не оценка качества.
2. **голос.** русский текст становится строчным в начале предложений; `GitHub`, `ZIP`, `SVG`, `PNG`, `README`, `CI`, названия языков и формула сохраняют технический регистр. рекламные и размытые обещания убираются, живой образ «полевого журнала» остаётся.
3. **визуальный слой.** сохраняем бумагу, чернила, marigold и coral из исходной системы, но делаем композицию более журнальной: яснее иерархия, меньше декоративного шума, заметнее дата и источник, отдельная полоса действий, аккуратные состояния загрузки/ошибки/пустого результата. мобильная версия и `prefers-reduced-motion` остаются обязательными.
4. **github‑страница.** README становится входной страницей проекта: короткое объяснение, ссылка на демо после публикации, локальный запуск, источники, приватность, формула и ограничения. добавляется workflow для GitHub Pages и шаблон описания проекта через метаданные страницы. факты о возможностях не расширяются без подтверждения.
5. **надежность.** сообщения об ошибках и статусы не должны оставлять пользователя в неоднозначном состоянии. при восстановлении share‑снимка отключается только повторный анализ без исходного архива; сброс возвращает полный стартовый сценарий. проверяется итоговый поток на URL, ZIP, папке, битом архиве и повреждённой ссылке.

## границы

код анализатора и формата share меняется только там, где это нужно для исправления найденной несогласованности или безопасного пользовательского потока. имена экспортируемых функций и формула остаются совместимыми с текущими тестовыми страницами.

## проверка

- `node --check` для всех модулей;
- браузерные fixture‑тесты из `src/*.test.html` через локальный статический сервер;
- ручной smoke‑проход: пустой экран, публичная ссылка, ZIP, папка, битый ZIP, повреждённый hash, reset, повторный анализ, share, SVG и PNG;
- проверка текста: публичные строки в `index.html`, `src/app.js`, `src/sources.js`, `src/share.js`, `README.md` и GitHub metadata не начинаются с прописной без причины и не обещают неподтверждённых возможностей.
