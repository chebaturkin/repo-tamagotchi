# Repo Tamagotchi

посмотрим на репозиторий как на маленькое живое существо. Repo Tamagotchi берёт структуру публичного GitHub‑репозитория, ZIP или папки, считает несколько понятных сигналов и рисует SVG‑питомца с характером.

это игрушка для наблюдения, а не ревью кода. числа описывают форму архива — файлы, языки, документацию и настройки. они ничего не говорят о качестве, возрасте или авторе проекта.

**[открыть демо](https://chebaturkin.github.io/repo-tamagotchi/)**

## как начать

откройте демо или запустите проект локально:

```bash
python3 -m http.server 4173
```

затем перейдите на `http://localhost:4173`. сборка и backend не нужны. после загрузки страницы локальный сценарий продолжает работать без сети.

## что можно принести

- **ссылка GitHub.** вставьте адрес вида `github.com/owner/repo`. протокол можно не писать. приложение запрашивает публичный архив `codeload.github.com/owner/repo/zip/HEAD` без токена. если GitHub не пропустит запрос из‑за CORS, лимита, таймаута или закрытого репозитория, загрузите ZIP;
- **ZIP.** нажмите «загрузить ZIP» или перетащите архив на поле. поддерживаются обычные stored/deflate‑записи, не больше 10 000 записей и 64 МБ после распаковки;
- **папка.** выберите папку целиком или перетащите её в поле. файлы читаются через File API прямо в браузере.

из анализа убираются `.git`, `node_modules`, сборочные каталоги и бинарные файлы. общий корень ZIP от GitHub нормализуется, поэтому ссылка и скачанный архив дают один и тот же результат.

## откуда берётся характер

у каждой характеристики шкала от 0 до 100. сначала считаются сигналы включённых текстовых файлов, затем применяется формула:

```text
score = clamp(round(35 + 65 × Σ(weight × signal)), 0, 100)
```

нормализация использует фиксированные ориентиры: 500 файлов, 5 MB текста, 12 расширений, 6 языков и 6 уровней глубины. результат не зависит от текущего времени, имени автора или истории коммитов.

- **энергия** — размер набора файлов, объём текста, исходники и скрипты;
- **любопытство** — языки, расширения, документация, примеры и notebooks;
- **устойчивость** — тесты, CI, конфиги и lock‑файлы;
- **хаос** — разнообразие расширений, глубина путей, файлы в корне и неизвестные расширения. высокий хаос означает разнородную структуру, а не плохое качество;
- **опыт** — манифесты, документация, лицензия, тесты, CI и конфиги. это следы оформленности архива, а не его возраста.

рядом со шкалой раскрывается исходный сигнал: сколько файлов нашлось, какие языки определились, есть ли README, лицензия, тесты и настройки.

## снимок и экспорт

кнопка «скопировать снимок» сохраняет компактный JSON‑снимок версии 2 в hash‑части адреса. исходные файлы и их содержимое в ссылку не попадают. такой адрес можно отправить другому человеку — журнал восстановится без исходного архива.

питомца можно скачать как SVG или PNG прямо из браузера.

## приватность и ограничения

локальные ZIP и папки никуда не загружаются. внешний запрос выполняется только для введённой публичной ссылки GitHub. приложение не использует API‑ключи, авторизацию, базу данных или внешнюю AI‑модель.

архив проходит ограничители по количеству записей и объёму распаковки. повреждённые, зашифрованные, многотомные и неподдерживаемые ZIP‑записи получают ясное сообщение с предложением выбрать другой источник.

## GitHub Pages

проект публикуется из корня репозитория через `.github/workflows/pages.yml`. workflow запускается после push в `main` или вручную из вкладки **Actions**. отдельный сервер для сайта не нужен.

## лицензии шрифтов

локальные файлы шрифтов лежат в `assets/fonts`. рядом с каждым семейством сохранён текст его лицензии:

- `Fraunces` — `assets/fonts/fraunces-OFL.txt`;
- `Literata` — `assets/fonts/literata-OFL.txt`;
- `Onest` — `assets/fonts/onest-OFL.txt`;
- `Azeret Mono` — `assets/fonts/azeretmono-OFL.txt`.
